# NewWorld

Текстовая ролевая игра для Telegram.

Игровая логика полностью отделена от Telegram и от нейросети. Это главное
архитектурное решение проекта: правила можно проверять тестами, сюжет —
писать без программиста, а оболочку (Telegram, веб, Mini App) менять,
не трогая игру.

## Быстрый старт

```bash
pip install -r requirements-dev.txt

# сыграть в терминале — ни токена, ни сети не нужно
python -m newworld.cli content/olhovets.yaml

# тот же забег ещё раз (одинаковые броски)
python -m newworld.cli content/olhovets.yaml --seed 42

# запустить бота
export NEWWORLD_BOT_TOKEN="токен от @BotFather"
python -m newworld.bot content/olhovets.yaml
```

Тесты:

```bash
python -m pytest
```

## Как устроено

```
newworld/
  core/          игра: правила, состояние, случайность
    dice.py        броски и проверки характеристик
    models.py      персонаж и состояние забега
    events.py      факты о случившемся
    content.py     загрузка и проверка сюжета из YAML
    engine.py      единственное место, где меняется состояние
    creation.py    генерация персонажа
  narrator/      как факты превращаются в текст
    base.py        интерфейс рассказчика
    template.py    рассказчик на авторском тексте (без нейросети)
  storage/       сохранения в SQLite
  bot/           Telegram: тонкий слой поверх игры
  cli.py         игра в терминале
content/         сюжеты
tests/           тесты
```

Поток одного хода:

```
нажатие кнопки
  -> bot/service.py    находит сохранение, проверяет актуальность кнопки
  -> core/engine.py    бросает кости, применяет эффекты, отдаёт список событий
  -> narrator/         описывает события словами
  -> bot/app.py        перерисовывает сообщение сцены
```

Движок возвращает **факты** (`ItemGained`, `DamageTaken`, `CheckRolled`), а не
текст. Рассказчик их **излагает**. Поэтому рассказчика можно заменить
нейросетевым, и игра от этого не станет менее честной: нейросеть не решает,
попал ли игрок и сколько у него хитов.

### Два решения, которые стоит знать заранее

**Одно сообщение на сцену.** Бот не шлёт новое сообщение на каждый ход, а
перерисовывает старое. Так игрок не листает простыню, и бот не упирается в
ограничение Telegram (примерно 20 сообщений в минуту в один чат).

**Короткий `callback_data`.** В кнопку Telegram помещает 64 байта, поэтому
туда кладётся не описание действия, а его адрес: `a:<ход>:<номер варианта>`.
Номер хода нужен, чтобы кнопка из прокрученного вверх сообщения не сработала
повторно.

## Как писать сюжет

Сюжет — обычный YAML, код трогать не нужно. Пример целиком лежит в
`content/olhovets.yaml`.

```yaml
start: crossroads          # с какой сцены начинается игра

scenes:
  - id: crossroads         # уникальный идентификатор сцены
    title: Перекрёсток
    text: |
      Описание, которое видит игрок.
    options:
      # 1. Простой вариант: сразу срабатывает
      - id: go_village
        label: Идти в деревню      # надпись на кнопке
        text: Ты идёшь по дороге.  # что показать после выбора
        effects:
          - type: gold
            amount: -5
        goto: village              # в какую сцену перейти

      # 2. Вариант с проверкой: два разных исхода
      - id: search
        label: Обыскать телегу
        check:
          ability: wis             # str / dex / con / int / wis / cha
          dc: 12                   # сложность: 10 — просто, 15 — трудно, 20 — очень
        on_success:
          text: Ты находишь фонарь.
          effects:
            - type: item_gain
              value: Фонарь
        on_failure:
          text: Ты режешь ладонь о гвоздь.
          effects:
            - type: damage
              amount: 2

      # 3. Вариант с условием: показывается не всегда
      - id: open_door
        label: Открыть дверь ключом
        requires:
          items: [Ключ]
        goto: cellar

  - id: village
    title: Деревня
    text: Финальный текст.
    ending: true            # сцена завершает забег
```

**Эффекты** (`effects`):

| Эффект | Поле | Что делает |
|---|---|---|
| `damage` | `amount` | снимает хиты |
| `heal` | `amount` | лечит (не выше максимума) |
| `gold` | `amount` | даёт или отнимает монеты (в минус не уходит) |
| `item_gain` | `value` | кладёт предмет в инвентарь |
| `item_lose` | `value` | убирает предмет |
| `flag` | `value` | помечает, что событие произошло |

**Условия** (`requires`) — вариант показывается, только если всё выполнено:

| Условие | Значение |
|---|---|
| `flags` | перечисленные флаги установлены |
| `not_flags` | перечисленных флагов нет |
| `items` | предметы есть в инвентаре |
| `min_gold` | монет не меньше указанного |

Сюжет проверяется при загрузке: опечатка в названии сцены, эффекта или
характеристики — это ошибка при старте с понятным сообщением, а не
сломанная игра у живого игрока. Отдельный тест следит за тем, чтобы
`content/olhovets.yaml` всегда оставался валидным.

## Броски

Проверка — `1d20` плюс модификатор характеристики против сложности (DC).
Модификатор считается как `(значение - 10) // 2`, то есть 10-11 дают `+0`,
а 18 даёт `+4`. Натуральные 20 и 1 всегда решают исход: даже с огромным
бонусом единица провалит проверку.

Броски показываются игроку открыто — в проверяемые числа верят больше, чем
в формулировку «тебе не повезло».

Забег воспроизводится по сиду: `--seed 42` в терминале повторит ту же
последовательность бросков. Сид сохраняется в состоянии игры, поэтому любую
жалобу игрока можно воспроизвести у себя.

## Что дальше

Рассказчик на нейросети встаёт рядом с шаблонным: нужно унаследоваться от
`narrator.base.Narrator` и реализовать один метод `narrate(turn)`. Движок,
сохранения и бот при этом не меняются — на вход рассказчику приходят те же
факты.
